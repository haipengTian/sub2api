# v0.2.19-custom.2

新增 Muse2API 图片和视频通道，通过统一的 Sub2API 地址使用 `muse-image` 和 `muse-video`。
官方基线沿用 v0.2.19，本次不融合新的上游版本。

## 生图和参考图编辑

- `muse-image` 支持 `/v1/images/generations` 和 `/v1/images/edits` 的 API Key 转发。
- 保留 JSON 与 multipart 请求中的模型、提示词、参考图和扩展参数，支持 `b64_json` 响应。
- 频道映射、账号映射与复合分组可指向 Muse 图片模型。
- 仅使用 OpenAI 兼容 API Key 账号；不混入 ChatGPT OAuth / SetupToken 图片通道。
- 后台账号测试识别 Muse 图片模型，展示图片提示词、调用生图接口并显示结果。
- 原有 GPT、Grok、Gemini 的图片模型校验不变，未知模型仍拒绝。

## 异步视频

- `muse-video` 支持 JSON 文生视频、参考图视频，包含提交、进度查询、鉴权下载与 Range。
- OpenAI API Key 账号须明确声明 `muse-video` 模型，支持复合分组路由。
- 任务 ID 使用 `muse:` 前缀，绑定用户、Key、分组和创建账号；完成后只计费一次。
- 默认请求时长为 Muse 的 6 秒，保留超过 15 秒的请求时长；不改原有 Grok 时长规则。
- 下载固定使用配置的 Muse2API 媒体路径，不请求上游任意 URL，不外泄上游 Key。
- 麦麦照片插件尚未增加视频调用工具，需要视频客户端走异步接口。

配置、计费和验收步骤见 [通过 Sub2API 使用 Muse 图片和视频](../muse-images.md)。

## 前端安全升级

- Vue I18n 与消息编译器升级至 11.4.16，修复 GHSA-83rm-6c8r-g728。
- `decode-uri-component` 升至 0.5.1，修复 GHSA-qr28-fpjm-wq7f。
- CI、安全扫描和发布前端统一使用 Node 24，匹配新依赖和现有 Docker 构建环境。

## 服务器更新

待该固定版本 Release 成功后，由服务器操作者执行：

```bash
cd /opt/server-ops/sub2api
bash update.sh ghcr.io/haipengtian/sub2api:0.2.19-custom.2
bash status.sh
```

本次没有新增 SQL 迁移，沿用 v0.2.19-custom.1 的数据库结构。若服务器尚未升级到该基线，
先阅读 [v0.2.19-custom.1 升级影响](0.2.19-custom.1.md#升级影响)。
更新脚本会暂停应用、备份并检查新版本健康状态，有短暂中断。

服务器部署后，分别验证普通生图、上传糯糯参考图编辑、异步视频三步流程，以及原有聊天和计费。
本次本地验证没有调用真实 Muse 生图/视频，也没有修改服务器上的账号、Key、模型路由或麦麦配置。
