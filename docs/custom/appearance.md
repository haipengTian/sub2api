# 三种界面风格

默认使用现代风格，用户可以在侧栏底部或登录/注册页面选择「现代风格」「经典风格」「Credit 风格」。
经典风格继续使用上游现有样式与布局。浅色/深色切换独立于皮肤切换。

Credit 风格移植 Credit × CDK 参考项目的中性白底、紫色选中态、紧凑虚线表格、圆角卡片与短动效。
覆盖公共布局、表单、菜单、弹窗、分页、用户与管理仪表盘和认证页面；沿用同一套业务组件及功能开关。
具体来源、样式尺寸与维护入口见 [Credit 组件风格](credit-style.md)。

现代风格通过留白区分侧栏、顶栏与主体，移除这些区域之间的边框和阴影；经典风格保留原分隔线。
现代风格的卡片、按钮、输入框、表格、菜单、弹窗及头像外框统一使用直角，包含弹出的公共组件。
默认 Logo 与网站图标使用 `frontend/public/logo.svg` 中的像素奥特曼飞行图案，包含轻微浮动与尾焰动画。
系统开启减少动态效果时动画停止；标签页图标是否播放动画取决于浏览器支持。
管理员配置的自定义网站 Logo 仍优先使用。

## 加载反馈

现代和 Credit 风格的仪表盘首屏使用骨架占位，概览数字在 480ms 内平滑到达实际值，金额沿用原有格式与精度。
数字的辅助阅读文本直接提供实际值，不逐帧播报；表格中的明细金额直接显示。
表格、图表与最近使用记录刷新时保留已有内容，通过顶部细进度条提示正在更新；已完成的空结果也会保留。
仪表盘刷新按钮等待相关请求完成，避免重复触发；快速切换图表筛选时仅采用最新请求结果。
占位和内容淡入采用短动画；系统开启减少动态效果时数字、图表与 CSS 动画均停用。
经典皮肤继续使用原来的旋转图标和表格占位。

## 表格与列表

公共 DataTable 的表头、行留白、固定列、勾选高亮、状态标签和滚动条统一适配现代风格。
固定列使用与当前行相同的背景，移除旧渐变阴影；横向滚动时保留细边界，排序、选择与虚拟滚动继续使用原逻辑。
密钥操作区使用紧凑的图标加文字按钮，保留删除警示色；金额与状态含义不变。
分页改为独立直角按钮，当前页绿色高亮，支持按钮换行、键盘焦点与每页条数选择。
手机列表使用字段与数值的直角卡片，筛选控件适配窄屏；空结果和刷新反馈沿用已有加载逻辑。
用户仪表盘的模型明细保持紧凑间距，渠道详情、渠道监控、邀请列表和批量生图说明表格同步适配。
共享表格改动覆盖密钥、使用记录、订单及采用公共组件的后台页面，经典皮肤沿用上游样式。

## 选择与兼容

- 皮肤保存在当前浏览器的 `sub2api-skin`，取值 `modern`、`classic` 或 `credit`。已有现代/经典选择保持不变。
- 明暗模式继续使用上游的 `theme`，已有选择会保留；无选择时遵循系统明暗设置。
- 存储不可用或皮肤值无效时默认现代风格，仍可在本次页面中切换。
- 首屏在 `index.html` 初始化外观，生产环境沿用后端 CSP nonce 占位符。
- 偏好只保存在浏览器，不同步到账户或其他设备。

## 第一批范围

现代风格覆盖侧栏、顶栏、登录等认证表单、用户仪表盘、密钥表格、渠道状态。
用户仪表盘新增余额与快捷操作区，保留既有请求、Token、实际/标准费用、性能和平台配额数据。
购买入口遵循支付开关、计费模式和 simple mode，复制地址遵循本站 API 地址设置。
渠道状态保留 v1/v2 选择、状态文字、配额与详情交互。
管理员后台加入管理工作台、账号摘要和账号/用户/分组/设置快捷入口；管理菜单与个人空间分区显示。
管理首页沿用统计数据、费用格式和图表筛选，现代皮肤接入数字动画、首屏骨架与刷新进度提示。
后台表格、筛选控件、选中标签及系统设置导航统一适配白绿黑灰、直角风格，经典皮肤保留原布局。
快捷入口继续遵循 simple mode；身份、菜单开关、路由权限和业务 API 保持原逻辑。现代与经典风格保留原公开首页；Credit 的公开首页和认证页见 [Credit 风格说明](./credit-style.md)。

## 上游融合维护

现代样式集中在 `frontend/src/styles/custom/modern.css`，新展示组件在 `frontend/src/components/custom/`。
Credit 样式集中在 `frontend/src/styles/custom/credit.css`，字体在 `credit-fonts.css` 与 `frontend/public/fonts/credit/`。
`useAppearance.ts` 集中管理偏好与切换；Tailwind 主色通过 CSS 变量区分皮肤，经典色值保持原值。
公共布局与业务页仅接入样式标记或展示组件，三种风格使用同一数据、权限和 API。
同步上游时重点检查布局模板、Tailwind 配色、认证页 slot、渠道卡片结构与首页入口。
独立样式降低融合修改范围，不能保证未来上游变化没有冲突。
